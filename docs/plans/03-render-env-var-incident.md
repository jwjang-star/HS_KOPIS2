# Render 환경변수 설정 트러블슈팅 기록 (2026-08-05)

Phase 1/2 배포 후 `KASI_API_KEY`/`FESTIVAL_API_KEY`를 Render에 등록하는 과정에서 실제로 겪은 문제와 해결 과정. 다음에 Render 환경변수를 또 만지게 되면 이 문서부터 볼 것.

## 겪은 문제 3가지

**1. Encoding 키를 그대로 붙여넣음 → 이중 인코딩**
data.go.kr에서 복사한 값(`...NJ%2BopWrI...Mw%3D%3D`, 퍼센트 기호 포함)을 그대로 Render에 넣으면, `main.py`의 `requests.get(..., params={...})`가 그 값을 다시 한 번 URL 인코딩해버려서 `%2B`가 `%252B`로 이중 인코딩됨. data.go.kr은 이걸 무효한 키로 판단해 403(`SERVICE_KEY_IS_NOT_REGISTERED_ERROR`)을 반환. → Render엔 반드시 **Decoding 값**(퍼센트 기호 없이 `+`, `=`가 그대로 있는 원본)을 넣어야 함.

**2. 값 끝에 줄바꿈이 딸려 들어감**
1번을 고친 뒤에도 여전히 403이 남아서 로그를 다시 보니 URL 끝에 `%0A`(줄바꿈)가 붙어있었음. 메모장 등에서 키가 적힌 줄 전체를 복사할 때 줄바꿈까지 같이 복사된 것으로 추정. → 값 입력 후 **End 키로 커서를 끝까지 이동시켜 눈으로 직접 확인**하거나, 붙여넣고 나서 Backspace로 끝의 공백/개행을 지우는 습관이 필요.

**3. "200 OK"는 성공의 증거가 아님**
`/api/holidays`, `/api/festivals/sync` 둘 다 내부에서 외부 API 호출이 실패해도 예외를 잡아 **항상 HTTP 200 + `status:"success"`**를 반환하도록 설계되어 있음(키 없어도 기존 기능이 안 깨지게 하려는 의도된 설계, [[01-holiday-integration]] 참고). 그래서 Render 로그에 찍히는 `"GET /api/holidays... HTTP/1.1" 200 OK`는 키가 틀렸을 때도 똑같이 찍힘 — **응답 바디의 실제 데이터(`periods`/`holidays`/`total`)가 비어있는지를 봐야** 진짜 성공 여부를 알 수 있음. 디버깅 중 이걸 헷갈려서 "200 OK 떴는데 왜 안 되지"라는 혼선이 있었음.

## 진단에 실제로 도움된 방법

Render Logs 탭에서 뜨는 에러 줄(`🚨 KASI 공휴일 API 호출 실패 (2026): 403 Client Error: ... ServiceKey=...`)이 **문제 진단의 핵심 단서**였음 — 실패한 요청의 전체 URL이 그대로 로그에 찍히므로, 거기 담긴 `ServiceKey=` 값을 보면 이중인코딩/줄바꿈 여부가 바로 눈에 보임. 다음에도 데이터가 안 뜨면 추측하지 말고 **로그의 실제 에러 줄부터 요청해서 볼 것**.

## 별개 해프닝 — GAS_URL

Render 환경변수를 이것저것 만지던 중 `GAS_URL`(이메일 발송 웹훅)을 잘못 건드린 것 아니냐는 걱정이 있었음. `GAS_URL`/`SHEET_CSV_URL` 둘 다 `main.py`에 하드코딩된 fallback이 없어서(`os.environ.get("GAS_URL", "")`처럼 기본값이 빈 문자열), **잃어버리면 코드/깃 기록 어디에서도 복구 불가** — 유일한 복구 경로는 GAS_URL은 script.google.com의 "배포 관리"에서 기존 웹앱 URL 재확인, SHEET_CSV_URL은 원본 구글 시트의 게시 설정 재확인뿐. 결과적으로는 실제 값 손상이 아니라 **테스트 발송 시 지역을 잘못 선택한 사용자 실수**였음(메일 자체는 정상 발송됨) — 하지만 이 리스크 자체는 여전히 유효하므로, Render 환경변수 탭에서 작업할 땐 **의도한 필드만 수정하는지 매번 확인**할 것.

## 최종 확인 (2026-08-05)

`/api/holidays?year=2026` → 연휴 11개 구간·공휴일 22건 정상 반환. `/api/festivals/sync` → `total:1300, unmatched_region:0` 정상. 둘 다 프로덕션에서 실데이터로 확인 완료.
