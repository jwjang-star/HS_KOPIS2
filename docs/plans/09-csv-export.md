# Phase 9 — 그리드 뷰 CSV 다운로드

**상태: 구현 + 로컬 검증(운영 API·로컬 API 둘 다) 완료, 미배포(커밋 전, 작업트리에만 반영됨. 기준 커밋 `43f3438` 위에 `main.py`+`index.html` 수정).**

## 배경

그리드 뷰(공연/축제/스포츠)는 화면 조회만 가능하고 로드된 목록을 파일로 내보낼 방법이 없었음. 사용자가 화면에 로드된 데이터를 엑셀(엑셀에서 바로 열리는 CSV)로 받고 싶어함.

## 결정된 사양

- **대상**: 그리드 뷰만 (캘린더 뷰 제외)
- **내보내는 범위**: 현재 활성 소스탭(공연/축제/스포츠) + 현재 지역탭·기간·장르·상태 필터로 **이미 화면에 로드된** 데이터. 추가 API 재조회 없음(페이지네이션도 현재 페이지만).
- **형식**: CSV, UTF-8 BOM 포함(엑셀 한글 깨짐 방지). 새 의존성 없음.
- **컬럼 4개**: 날짜, 지역명, 카테고리, 이벤트 일정명

## 구현

기존 데이터 소스·필터 로직 재사용, 새 API 없음:
- 공연: `lastItems` + `renderList()`와 동일한 `onlyNew`(🆕 신규만) 필터
- 축제/스포츠: `lastFestivals` + `doFestivalSearch()`와 동일한 `kind==='sports'` 필터

**`exportCsv()` / `csvEscape()`** (`index.html`, `renderList()` 바로 다음에 추가):
- `sourceMode`별로 배열 선정 → 비어있으면 `alert('내보낼 데이터가 없습니다')`
- 4컬럼 매핑, RFC4046식 CSV 이스케이프(쉼표·따옴표·줄바꿈 포함 필드는 큰따옴표로 감싸고 내부 `"`는 `""`로)
- `﻿` BOM + `Blob(type:'text/csv;charset=utf-8;')` → 임시 `<a download>` 클릭 트리거 → `URL.revokeObjectURL` 정리
- 파일명 `KOPIS_{공연|지역축제|스포츠}_YYYYMMDD.csv`

**지역명 컬럼 소스**:
- 축제·스포츠: `REGION_LABEL[item.region]` — 항목별로 정확함
- 공연: `item.area || REGION_LABEL[selCode] || '전체'` — 아래 "지역명 버그 수정" 참고

**버튼**: `.lhead`(`#lcnt` 옆) `margin-left:auto`로 우측 정렬, `.btn-csv` 스타일 신규 추가(기존 `.btn-go`/`.btn-mail`과 같은 shape, 회색 계열).

## 지역명 버그 수정 — `main.py`가 KOPIS `<area>` 필드를 버리고 있었음

최초 구현 때는 "공연 탭은 항목별 지역이 아예 없다"고 판단하고, 지역 "전체" 탭에서 내보내면 전 행이 "전체"로 찍히는 걸 알려진 제약으로 남겼음. 사용자가 실사용 중 "공연 API도 지역 구분이 있지 않냐"고 지적 → KOPIS 원본 API를 직접 curl로 확인해보니 **`<db>` 항목마다 `<area>서울특별시</area>`가 실제로 내려오고 있었고, `main.py`의 XML 파싱 루프(`get_kopis_data`, 기존 L120-131 `item = {...}`)가 그 태그를 그냥 안 뽑고 버리고 있었던 것**이 원인. 프론트 워크어라운드가 아니라 백엔드에서 필드 하나 추가로 노출하는 근본 수정으로 처리:

- `main.py` `/api/kopis`: `item` dict에 `"area": db.findtext('area') or ""` 한 줄 추가. `SendRequest.performances`가 이미 느슨한 `Dict` 타입이라(의도적으로 그렇게 되어 있음, 주석 참고) 필드 추가가 메일 발송 경로에 영향 없음. 그 외 기존 필드·NEW 판별·Supabase 로직 전부 무변경.
- `index.html` `exportCsv()`: 공연 탭 지역명을 `item.area`(원본 그대로, 예: "서울특별시") 우선 사용, 비어있을 때만 `REGION_LABEL[selCode]` 대체.
- `item.area`는 KOPIS 원본 풀네임(`서울특별시`, `전북특별자치도` 등)이라 `REGION_LABEL`의 축약형("서울" 등)과 표기가 다름 — 정확성을 우선하고 별도 축약 매핑 테이블은 만들지 않음(행정구역 개편 대응 부담 대비 실익 낮다고 판단).

- 콘솔 에러 없음

**2026-09-30, 지역명 수정 후 — 로컬 API**(`uvicorn main:app --port 8000` + `srv-url`을 localhost로 교체, 지역탭 "전체" 유지): 공연 탭 CSV 재다운로드 → 지역명이 항목별로 실제 다르게 출력됨 확인(서울특별시 86 · 부산광역시 6 · 대전광역시 3 · 대구광역시 2 · 충청남도 2 · 전북특별자치도 1). 지역 "전체" 탭에서도 더 이상 "전체"로 뭉개지지 않음.
